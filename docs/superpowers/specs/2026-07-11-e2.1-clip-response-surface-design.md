# E2.1 Clip Radius Defense Response Surface Design

## 1. 文档状态与阶段边界

本文档定义证据链 E2 的第一个可交付阶段：用单一、连续、可解释的
`clip_radius` 防御动作验证 aggregation defense 的可控性。

E2.1 不训练 defender 或 attacker，不实现 Best Response，不选择最终 observation，
也不声称 clipping 对所有攻击都有效。它只建立后续四时间尺度共同复用的防御动作边界，
并用 matched response surface 证明该动作确实改变联邦聚合和独立评估结果。

四时间尺度中的定位如下：

```text
FL Round:        DefenseAction -> Aggregator -> RoundTransition
Episode:         固定动作编排多个 rounds，保持 RNG 隔离
Best Response:   后续 policy 输出同一动作，不改物理执行语义
Meta Iteration:  后续跨任务复用同一 codec、动作记录和 evaluator
```

## 2. 目标与可证伪命题

E2.1 验证以下命题：

1. `clip_radius` 能通过纯 aggregation operator 改变 aggregate delta；
2. clipping 对每个 client update 施加可手工验证的全模型 L2 上界；
3. matched clean/attack Episode 扫描能得到非平坦响应面；
4. 至少存在两个动作点，在 clean utility 或 attack harm 上产生可辨识差异；
5. 防御动作不改变 client sampling、客户端训练随机流或 oracle 信息边界。

如果响应面平坦，E2.1 判定不通过。此时优先检查动作范围、攻击 fixture、聚合信号和
评估灵敏度，不进入 RL。

## 3. 方案选择

采用显式动作与聚合器装饰器：

```text
normalized policy value
 -> ClipRadiusActionCodec
 -> DefenseAction(clip_radius)
 -> ClippedAggregator(base=FedAvg, radius=clip_radius)
 -> existing RoundEngine / AttackRoundEngine
```

不把 `clip_radius` 加入 `RoundRequest`。联邦核心继续只依赖 `Aggregator` protocol，
不认识具体防御 family 或参数。不在 response-surface runner 内创建匿名聚合函数，确保
同一物理动作实现可被后续 policy、Best Response 和 Meta Iteration 直接复用。

## 4. 模块与接口

### 4.1 DefenseAction

`meta_stackelberg/security/defenses/actions.py` 提供不可变动作：

```python
@dataclass(frozen=True)
class DefenseAction:
    clip_radius: float
```

`clip_radius` 必须是有限正数。E2.1 不使用 `None` 或 infinity 表示 no-op，避免无法进入
有限 action space。精确 no-op baseline 由普通 `FedAvg` 表示；响应面中的 reference
radius 必须大于或等于该 fixture 所有 client update norm，且通过测试证明与 FedAvg exact。

### 4.2 ClipRadiusActionCodec

`meta_stackelberg/security/defenses/action_codec.py` 提供一维线性 codec：

```python
ClipRadiusActionCodec(min_radius: float, max_radius: float)
codec.decode(normalized_action: np.ndarray) -> DefenseAction
codec.encode(action: DefenseAction) -> np.ndarray
```

归一化空间固定为 `[-1, 1]`，物理半径使用闭区间
`[min_radius, max_radius]`。构造参数必须是有限正数且 `min_radius < max_radius`。
输入必须是 shape `(1,)` 的有限浮点数组；越界、错误 shape、NaN 和 infinity 均 fail fast。
encode/decode 在浮点容差内互逆，端点精确映射。

codec 只负责坐标变换，不选择动作、不观察 transition、不计算 reward。

### 4.3 ClippedAggregator

`meta_stackelberg/security/defenses/clipping.py` 提供：

```python
ClippedAggregator(base: Aggregator, clip_radius: float)
aggregator.aggregate(updates: Sequence[ClientUpdate]) -> ModelState
```

对每个 client delta 的所有 tensors 联合计算全局 L2 norm：

```text
scale_i = min(1, clip_radius / ||delta_i||_2)  if norm > 0
scale_i = 1                                    if norm = 0
clipped_delta_i = scale_i * delta_i
```

随后保留 `client_id`、`num_examples`、`is_malicious` 和 metadata，构造内部临时 update，
并委托 `base.aggregate`。operator 不读取 `is_malicious` 或 metadata 来决定裁剪，不修改输入
update、delta 或 ndarray，不改变样本权重。

radius、输入结构、dtype 和 finite 校验在委托前完成。缩放结果保持每个 tensor 的原 dtype；
浮点舍入后 norm 不得超过 radius 加与 dtype 对应的数值容差。

### 4.4 Defense diagnostics

聚合协议当前只返回 `ModelState`，因此 E2.1 不改变 `Aggregator` protocol，也不把私有统计
塞进 `RoundTransition.public_signals`。`ClippedAggregator` 提供无状态纯函数式
`summarize(updates) -> ClippingSummary`，response-surface runner 在相同输入上独立计算：

- client count；
- clipped client count/fraction；
- pre-clip norm min/median/max；
- clip radius。

summary 不含恶意身份、逐客户端值或 oracle metric。运行时不得依赖上一次 aggregate 调用的
mutable cache，以支持并行 task 和 deterministic replay。

## 5. Response Surface Runner

`meta_stackelberg/experiments/defense_response_surface.py` 提供研究编排，不进入 round engine：

```python
evaluate_clip_response_surface(
    fixture,
    radii: Sequence[float],
    seeds: Sequence[int],
) -> ClipResponseSurface
```

fixture 明确提供：

- 初始 `RoundState` / model snapshot；
- clean 与固定攻击 Episode factory；
- `FedAvg` baseline；
- clean evaluator 与 attack-specific evaluator；
- action-cost 函数和 task fingerprint。

每个 `(seed, radius, branch)` 都从独立 clone 的同一 snapshot 开始。runner 不复用已经推进的
Episode、parent RNG、trainer 或 model。clean 与 attack 分支必须匹配 sample IDs、client child
seed 分配和初始模型；唯一允许差异是攻击 operator 和 defense radius。

每个点记录：

```python
ClipResponsePoint(
    seed,
    radius,
    branch,
    final_clean_loss,
    final_clean_accuracy,
    attack_harm,
    aggregate_norms,
    clipped_client_fractions,
    defense_cost,
    sampled_clients,
    final_random_snapshot,
)
```

`attack_harm` 由 fixture 的攻击 evaluator 定义：untargeted 使用 held-out loss harm，targeted
使用 source-only ASR。runner 不把不同攻击目标压成一个未经定义的统一指标。

## 6. 动作成本

E2.1 使用可解释、单调的相对约束成本：

```text
defense_cost(radius) = log(reference_radius / radius)
```

其中 `reference_radius` 是网格最大半径，且必须满足 no-clip reference gate。
成本在 reference 点为 0，半径越小成本越高。该成本只用于报告 trade-off，不作为训练 reward；
E4 前可以依据响应面重新标定。

## 7. 数据与信息边界

- ClippedAggregator 只能读取本轮提交给聚合器的 client updates；
- 不读取 held-out dataset、ASR、clean evaluator、未来状态或攻击标签；
- oracle evaluator 只在 Episode 完成后读取 final model；
- response-surface runner 可以汇总 oracle 指标用于离线报告，但不把它反馈到 Episode；
- `security` 不能导入顶层 `evaluation`，现有依赖边界测试继续成立；
- action codec 和 aggregation operator 不依赖实验 runner。

## 8. 验证策略

### 8.1 单元测试

- codec 构造、shape、finite、range 和 round-trip；
- 单 tensor 与多 tensor 的联合 L2 clipping 手算样例；
- zero delta、radius boundary 和 dtype preservation；
- sample-weighted FedAvg 委托语义；
- client order permutation invariance；
- 输入对象和 arrays 不变；
- no-clip reference 与 FedAvg exact；
- pure summary 无跨调用状态。

### 8.2 Contract 与集成测试

- `ClippedAggregator` 满足现有 `Aggregator` protocol；
- clean RoundEngine 与 AttackRoundEngine 无 defense-specific branch；
- 同 seed、不同 radius 的 sampling 与 RNG exact；
- 同 radius 重跑的 transition、metrics 和 summary exact；
- evaluator 只在 Episode 后调用；
- response point 拒绝非有限 metric 和不匹配 evaluation protocol。

### 8.3 E2.1 evidence fixture

先使用 E1.1 fixed untargeted Delta Reversal + FedAvg，因为其 harm 指标和 matched fixture 已有
证据，且 norm clipping 对放大/反向 delta 有直接可解释作用。使用至少三个固定 seeds 和至少
五个对数尺度半径，包括：强裁剪、中等裁剪、弱裁剪和经验证的 no-clip reference。

如果该 fixture 不能产生非平坦响应面，不替换为更容易通过的指标；报告失败并调整经单元测试
证明过窄或过宽的 action range。E2.2 再增加 `trim_ratio` 和攻击/聚合器矩阵。

## 9. E2.1 Gate

E2.1 只有同时满足以下条件才通过：

1. codec 对所有非法动作 fail fast，合法端点与 round-trip 成立；
2. 每个裁剪后 client delta 满足全模型 L2 bound；
3. no-clip reference 与 FedAvg aggregate、model、metrics exact；
4. 输入顺序不影响对称聚合，输入对象不变；
5. 所有 radius 分支 sampling、client RNG 分配和 parent RNG matched；
6. 三个声明 seeds 的重复运行 deterministic；
7. 至少一个已验证攻击 fixture 的 aggregate 或独立 held-out response surface 非平坦；
8. 至少两个 radius 点在 clean utility、attack harm 或 defense cost 上形成可报告差异；
9. oracle isolation 和依赖边界检查通过；
10. canonical `tests/meta_stackelberg` 与全仓测试通过。

“非平坦”必须在实施计划中预先给出数值阈值，不能看到结果后选择。报告必须列出所有网格点，
不得只展示最优点。

## 10. 失败处理与限制

- radius 非法、metric 非有限、protocol/version 不匹配时立即终止对应实验；
- 单个 seed 失败不能用其他 seed 的结果填补；
- runner 失败不得复用部分推进的状态；
- 三个 seeds 只作为阶段 gate，不支持总体统计或论文置信区间；
- clipping 只能证明本 fixture 中的可控性和 trade-off，不等同于通用鲁棒性；
- E2.1 不选择 defender reward 权重，不训练 policy，不证明 Stackelberg Best Response。

## 11. 后续衔接

E2.1 通过后按以下顺序继续：

1. E2.2：增加 `trim_ratio`、trimmed aggregation 和攻击/聚合器响应面矩阵；
2. E2 gate：冻结可辨识 action range、observation candidates 与 evaluator protocols；
3. E3：committed defender policy 下的 follower Best Response；
4. E4：固定任务、冻结 follower 的 defender adaptation；
5. E5：support/query 分离与 Meta Iteration；
6. E6：未见任务和 simulator-to-real 泛化。

所有阶段继续复用 E2.1 的物理动作、codec 和 aggregation operator，不建立第二套防御执行路径。
