# Paper-Aligned Meta-SG Dynamic TD3 Design

## 1. Authority and scope

This design is governed by the algorithms and parameter meanings in *Meta Stackelberg Game: Robust
Federated Learning against Adaptive and Mixed Poisoning Attacks* (arXiv:2410.17431) and its RL-attack
reference [15], *Learning to Attack Federated Learning: A Model-based Reinforcement Learning Attack
Framework*. Existing `meta_sg` code is a useful implementation reference but is not authoritative when it
adds undocumented scheduling, proxy selection, server-LR actions or query-gated updates.

The canonical implementation must preserve three distinct layers:

1. **BSMG environment:** one Markov step is one FL round; both policies act every round.
2. **Algorithm 1 meta-Stackelberg learning:** `N_A` attacker inner iterations and `N_D` defender/leader
   iterations retain the meanings and order in the paper.
3. **Algorithm 2 Reptile meta-RL:** `T` meta iterations, `K` sampled tasks and `l` task-adaptation steps
   remain separate from `N_A/N_D`.

Scaled smoke configurations may reduce counts and model/data size, but may not change action dimensions,
state semantics, nesting, update order or parameter names. Only a run using the declared paper configuration
may be called a paper-parameter run; smoke runs prove implementation, not reproduction.

### 2.2 Paper domains without fixed numeric bounds

The paper defines but does not give one global constant range for every physical action:

```text
alpha_t in (0, max selected-client update norm]
beta_t is a coordinate-trimming rate
epsilon_t / sigma_t is the post-training NeuroClip / Prun parameter
gamma_t >= 0
E_t is a positive integer local-search step count
lambda_t in [0,1]
```

The canonical code must label numeric decoder bounds as **implementation declarations**, not paper values.
Defaults below follow the paper-aligned legacy configuration where available and are frozen before evidence:

```text
alpha: relative [1e-6, observed max update norm]
beta: [0, 0.45]  # executable equal-tail trimming requires beta < 0.5
epsilon: [0.1, 10.0]
gamma: [0.1, 2.9]
E: integer [1, 19]
lambda: [0.05, 0.95]
fixed local-search trajectory count G: 1 for smoke, configurable for paper run
```

Every report must print these separately from explicit paper parameters.

### 2.3 Stable-Baselines3 defaults not printed in the paper

The paper names Stable-Baselines3 TD3 but does not enumerate target `tau`, policy delay, smoothing noise,
replay capacity or learning-start count. The implementation must version and report the selected SB3-compatible

tau=0.005, policy_delay=2, target_policy_noise=0.2, noise_clip=0.5

## 3. Per-round BSMG environment

One policy trajectory contains `H` FL rounds:

```text
s_t = compressed global model state
d_t ~ pi_D(. | s_t; theta)
u_t ~ pi_A(. | s_t, d_t; phi)  # white-box leader behavior
updates, reward_D, reward_A, s_{t+1} = FL_step(s_t, d_t, u_t)
```

The physical FL state remains the full model. Compression affects policy input only. Defender action is chosen
before current-round client updates exist. The Attacker knows the frozen Defender policy and observes its current
action; this explicit sequential information set is recorded in the threat model.

## 4. Paper-aligned Defender action

Raw action is exactly three-dimensional:

```text
d_t in [-1,1]^3 -> (alpha_t, beta_t, epsilon_t)
```

- `alpha_t`: global-L2 norm bound applied to each submitted client update;
- `beta_t`: equal-client coordinate-wise trimmed mean rate;
- `epsilon_t`: NeuroClip post-training range.

`alpha/beta` determine the actual FL transition each round. Following Remark 1, NeuroClip is evaluated on a
copy for per-step reward and does not change the intermediate FL state; it is applied to the delivered model at
the final round. A separate Prun experiment may replace epsilon by sigma but cannot mix both in one action.

This requires a canonical, tested NeuroClip operator and immutable `PaperDefenderAction`; the prior two-dimensional
E2 `DefenseAction` remains intact for historical evidence and cannot silently absorb the third parameter.

## 5. Paper-aligned RL Attacker action

Raw action is exactly three-dimensional, within one untargeted RL attack family:

```text
u_t in [-1,1]^3 -> (gamma_t, E_t, lambda_t)
```

The operator follows reference [15]: starting from the current global model, run `G` local-search trajectories,
each with `E_t` minibatch gradient-ascent steps on

```text
L(theta) = (1-lambda_t) * empirical_loss(theta)
           + lambda_t * cosine(global_model - theta, benign_reference_direction)
```

and submit the scaled direction

```text
malicious_update = gamma_t * (global_model - mean(local_search_endpoints)).
```

All malicious clients controlled by the same attacker share the action. `E_t` uses deterministic rounding and
clamping; decoder endpoints, round-trip for representable integers and RNG ownership require direct tests.

IPM finite-scale response remains an E3 reference baseline but is not the adaptive policy used for paper-aligned
Meta-SG training.

## 6. Paper-aligned state compression

The main observation is the global model tail, not a hand-engineered update-statistics vector. Use the final two
learnable parameter tensors in the stable model weight list. For the paper MNIST CNN these are `fc1.weight` and
`fc1.bias`, giving the Meta-SG implementation's 1290-dimensional state. Selecting the final two module blocks
would incorrectly include `conv3` and create roughly 410k state dimensions. Values are flattened in stable order
and normalized by a versioned finite normalizer without changing the full FL transition state.

Attacker observation additionally includes the sampled malicious-client count. The declared white-box extension
appends current raw Defender action. Round progress and masks may be separate `MultiInputPolicy` dictionary keys;
update norms, oracle losses and attacker identity are not substitutes for the model-tail state.

## 7. Rewards and post-training evaluation

Untargeted paper rewards are transition-based model objectives:

```text
r_D^t = -F(post_defense_copy(w_g^t))
r_A^t = -F_attack(post_defense_copy(w_g^{t+1}))
```

For strict-competitive untargeted experiments, define attacker reward as the increase in the same declared loss
objective and Defender reward with the corresponding opposite sign/offset. The root/generated dataset used for
training reward is separate from held-out query data. Every reward stores scalar, clean-loss, post-defense effect,
attack objective and source protocol. Query metrics never enter replay, normalizers, gradients or checkpoint
selection.

## 8. Canonical TD3 implementation contract

Defender and every adaptive attack type own separate actor, twin critics, target networks, optimizers, replay
buffer, RNG and counters. Actor outputs bounded raw actions. Twin-critic target, terminal masking, delayed actor
update, target smoothing and Polyak update match SB3 TD3 equations and declared defaults.

Snapshots cover online/target networks, optimizer state, replay generation, counters, normalizer and schema.
Full fingerprints hash tensor dtype/shape/bytes plus optimizer/counter state. A freeze guard compares fingerprints
before and after every opposite-role block.

## 9. Algorithm 1: policy-level best response and leader update

Implement Algorithm 1 as its own runner with paper names:

```text
for leader iteration n_D = 0 .. N_D-1:
    sample K attack tasks/types from Q
    for each xi:
        theta_xi <- one-step or declared l-step adaptation from theta
        phi_xi(0) <- persistent policy for type xi

        freeze theta and all Defender state
        for k = 0 .. N_A-1:
            collect/sample H-step trajectory batches under theta, phi_xi(k)
            phi_xi(k+1) <- TD3 attacker update
        phi_BR_xi <- phi_xi(N_A)
        verify Defender full fingerprint exact

        freeze phi_BR_xi
        collect fresh trajectories under theta_xi, phi_BR_xi
        estimate/update the Defender objective for xi
        verify Attacker full fingerprint exact

    theta <- theta + kappa_D/K * sum_xi(defender_gradient_xi)
```

`N_A` counts attacker optimizer iterations inside one response search. `N_D` counts Algorithm 1 leader iterations.
No implementation may introduce `N_D` extra updates inside each leader iteration. Intermediate `phi(k)` values
are optimization iterates, not separately selected BRs; only `phi(N_A)` is the paper's approximate response.

## 10. Algorithm 2: Reptile meta-learning

Implement Algorithm 2 separately:

```text
for meta iteration t = 1 .. T:
    sample K tasks Xi_hat from Q
    for each xi:
        theta_xi(0) <- theta_t
        for j = 0 .. l-1:
            sample H-step trajectories under theta_xi(j)
            theta_xi(j+1) <- one TD3 task-adaptation update
    theta_{t+1} <- theta_t + meta_step/K * sum_xi(theta_xi(l)-theta_t)
```

For adaptive Meta-SG tasks, the task rollout uses the current type-specific response policy produced by the
Algorithm 1 response block. Composition order and whether response is refreshed at every adaptation step are
explicit experiment protocol fields; the default faithful protocol refreshes once per sampled task before the
`l` Defender adaptation steps, matching the paper's separation of response and task adaptation without concurrent
updates. Any alternate refresh cadence is an ablation and cannot replace the default evidence.

`T` is not multiplied into or aliased to `N_D`; `l` is not renamed `N_D`; reports show actual counts for all.

## 11. Configuration classes

`PaperMetaSGConfig` contains the explicit values in section 2.1 and rejects inconsistent aliases. It is immutable,
versioned and serializable. `ScaledMetaSGConfig` must be constructed from it by an explicit method that may override
only:

```text
T, K, H, l, N_A, N_D, trajectory batch count,
client/attacker counts, model/data sample limits, replay learning-start count.
```

It may not override action dimension, operator semantics, state encoder family, update order, reward source or
freeze requirements. Every result records both paper reference values and scaled actual values.

Initial deterministic smoke declaration:

```text
T=2, K=2, H=8, l=2, N_A=2, N_D=2
clients=6, untargeted attackers=3, sample_size=4
TD3 batch=16, learning_starts=16, hidden=(64,64), replay=4096
```

This is only a contract/replay test. Scientific evidence requires a separately approved larger scaled run or the
paper configuration; smoke results cannot satisfy performance claims.

## 12. Baselines and evaluation

All Defender policies are evaluated against their own freshly trained type-specific attacker BR:

- learned Meta-SG Defender;
- initial/untrained TD3 Defender;
- random three-dimensional Defender;
- fixed midpoint three-dimensional action;
- fixed specialized defenses from the declared paper-aligned grid;
- meta-RL without adaptive attacker BR;
- optional legacy implementation as a non-authoritative regression.

Independent query seeds and held-out data are used only after policies and response snapshots freeze. Comparisons
report clean accuracy/loss, attacker objective, full action trajectories and post-defense metrics.

## 13. Gates

### 13.1 Implementation conformance gate

1. Defender and Attacker actions are both 3D with correct physical semantics.
2. One environment step equals one FL round; both policies act each round.
3. Main state is the last-two-parameter-tensors model compression (1290 dimensions for paper MNIST).
4. `T/K/H/l/N_A/N_D` call counts match trace records exactly.
5. `N_A` block changes only Attacker; Defender block changes only Defender.
6. Algorithm 1 and Algorithm 2 have separate public runners and tests.
7. post-training defense copy does not alter intermediate FL state.
8. exact snapshot restore/replay and dependency boundaries pass.
9. paper and implementation-declared parameters are separately reported.
10. canonical and full repository suites fresh pass.

### 13.2 Scientific gate

After conformance passes, require on independent query trajectories:

1. `phi(N_A)` attacker improves over `phi(0)` or reaches a predeclared response-oracle plateau;
2. materially different frozen Defender policies induce different response behavior;
3. task-adapted Defender improves over its initialization;
4. meta initialization outperforms random initialization and no-adaptation baseline under equal budget;
5. learned Defender approaches the declared finite specialized-defense oracle;
6. improvement is absent from neither action behavior nor held-out objective.

Thresholds and run scale require a separate pre-run evidence plan; they may not be chosen after query results.

## 14. Delivery sequence

To prevent another semantically convenient but misaligned implementation, delivery is gated in this order:

1. paper parameter/action/state conformance records and codecs;
2. canonical NeuroClip-copy and 3D local-search RL attack operators;
3. BSMG per-round environment and exact replay;
4. SB3-compatible TD3 core and snapshot/freeze contracts;
5. Algorithm 1 trace-verified response/leader runner;
6. Algorithm 2 trace-verified Reptile runner;
7. scaled deterministic run, independent scientific Gate and complete report.

No later stage begins until the preceding conformance tests pass. The final report must list every deviation from
the paper rather than describing scaled settings as an exact reproduction.
