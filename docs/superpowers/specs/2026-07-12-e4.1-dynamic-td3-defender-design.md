# E4.1 Dynamic TD3 Defender with Policy-Level IPM Best Response Design

## 1. 目标与证据边界

E3.1r 已证明固定 Defender action 下，IPM finite-candidate follower response 能达到 query oracle，且
response 随 leader commitment 改变。E4.1 进入论文 Meta-SG 的动态 Markov-game 语义：Defender 和
Attacker 都在每个 FL round 根据状态输出连续动作；Attacker inner loop 对冻结的完整 Defender policy
求近似 best response；随后冻结 Attacker BR，仅更新 Defender。

本阶段在单一 IPM task 上验证：

1. Defender TD3 参数、逐轮动作和独立 query objective 都发生可解释改善；
2. learned Defender 优于 random policy 和 fixed midpoint；
3. learned Defender 接近动态环境下的有限 policy/action oracle；
4. Attacker inner loop 在 Defender bitwise 冻结时改善独立 attacker query objective；
5. 更换 Defender policy 时 attacker response 行为改变；
6. 双方从不在同一个优化阶段同时更新。

E4.1 不实现多任务 meta update、Reptile、未知 attack family 泛化或在线快速适应；这些属于 E5/E6。

## 2. 与 Meta-SG 原文的对应

遵循原文 BSMG：一个 Markov-game step 对应一个 FL round，状态为服务器可见的 FL 状态摘要，双方
策略在每轮产生动作：

```text
a_D^t ~ pi_D(. | s_t; theta)
a_A^t ~ pi_A(. | s_t, a_D^t; phi)
s_{t+1} ~ T(. | s_t, a_D^t, a_A^t)
```

采用两时间尺度近似：

```text
freeze theta
collect trajectories and update phi for N_A TD3 gradient steps
freeze phi_BR
collect fresh trajectories and update theta once
repeat the outer loop for N_D defender iterations
```

`N_A` 是一个 BR search 内的 optimizer steps，不是不同攻击方法数量，也不是每个 FL round 重新求
一次 BR。每个固定 attack type 只维护一个可 warm-start 的 attacker policy。

与论文不同的是本可信基线使用 `H=8`、二维 Defender action 和一维 IPM action，以便 direct replay、
oracle comparison 和可证伪 Gate；不声称复现实验规模 `H=200/500`。

## 4. Episode 与逐轮时序

一个 episode 固定 task、dataset/model initialization protocol、horizon `H=8` 和 RNG root seed。

```text
reset -> s_0 with history_mask=0

for t in 0..7:
  defender raw action d_t = actor_D(s_t)
  decode d_t -> DefenseAction(alpha_t, beta_t)
  attacker observation z_t = concat(s_t, d_t)
  attacker raw action u_t = actor_A(z_t)
  decode u_t -> IPM scale_t
  sample/train benign clients
  craft IPM malicious updates using same-round benign references
  execute ClippedTrimmedMean(alpha_t, beta_t)
  evaluate server-visible root feedback
  create immutable transition and s_{t+1}
```

Defender action 必须在当轮 updates 产生前确定。pre-aggregation/update statistics 只能作为当轮 public
feedback 并进入下一轮 observation，禁止时间穿越。Attacker threat model 显式允许观察 current defense
raw/physical action 和 same-round benign updates；actor 先输出 scale，IPM operator 随后使用 benign mean。

## 5. Action codecs

### 5.1 Defender

复用 `ClippedTrimmedActionCodec`：

```text
raw d_t in [-1,1]^2
alpha_t in [0.01, 10.0]
beta_t in [0.0, 0.4]
```

执行路径固定为 per-client global-L2 clip 后 equal-client coordinate trimmed mean。第一版不加入
`server_lr`、post-training defense 或 discrete family selection。

### 5.2 Attacker

新增 `IPMScaleActionCodec`：

```text
raw u_t in [-1,1]
scale_t in [0.5, 8.0]
```

linear encode/decode、finite/shape/dtype/range fail-fast，边界和 round-trip 必须有直接测试。攻击方法始终
是 IPM；TD3 只优化方法内部的逐轮 scale。

## 6. Observation schema

Defender observation 是固定顺序、float32、finite 的向量：

```text
history_mask
round_progress
previous aggregate norm
previous benign update norm min / median / max
previous malicious submitted norm mean
previous clipped-client fraction
previous per-tail trim count normalized
previous retained count normalized
previous defender raw action[2]
previous attacker raw action[1]
previous root loss delta
```

共 14 维。初始 observation 除 `round_progress=0` 外为零，`history_mask=0`。后续
`history_mask=1`。所有尺度使用预声明 finite normalization/clipping；encoder 不读取 private diagnostics、
attacker identity、held-out dataset 或未来 transition。

Attacker observation 为 `concat(defender_observation, current_defender_raw_action)`，共 16 维。这使 follower
知道 leader policy 的当前行为，符合本阶段 white-box Stackelberg threat model。

## 7. Reward records

### 7.1 Attacker

复用并逐轮记录 E3 proxy：

```text
opposition
+ 0.25 * deployed survival
- 0.01 * log1p(scale^2)
```

其中 deployed delta 必须从 `state_after - state_before` 重建，不读 private aggregate diagnostic。

### 7.2 Defender

新增不可变记录：

```python
DefenderRewardRecord(
    scalar,
    root_loss_improvement,
    attack_survival_penalty,
    clip_cost,
    trim_cost,
    constraint_penalty,
    source='dynamic-ipm-defender-feedback-v1',
)
```

预声明第一版标量：

```text
root_loss_improvement
- 0.25 * max(0, attacker_survival)
- 0.01 * log(10 / alpha)
- 0.01 * beta / 0.4
- constraint_penalty
```

root dataset 与 held-out query dataset 按 indices 和 construction seed 独立。root loss 可用于训练；held-out
loss 只能在 frozen query 中使用。每个分量单独存储，所有值 finite。

## 8. TD3 contracts

Defender 和 Attacker 复用同一 canonical TD3 implementation，但拥有完全独立的 networks、optimizers、
target networks、replay buffers、step counters 和 RNG streams。

预声明 sandbox config：

```text
actor/critic hidden sizes = (64,64)
gamma = 0.99
target tau = 0.005
actor lr = critic lr = 1e-3
batch size = 32
replay capacity = 4096
policy delay = 2
target policy noise = 0.2
target noise clip = 0.5
exploration noise = 0.1
gradient norm cap = 10
```

Actor 输出 `tanh` raw action。Critic 输入 role observation 与该 role action；Attacker observation 已包含
current defender action，Defender critic 不接收 oracle/真实 attacker identity。

每次 `update()`：sample role-local batch、更新 twin critics；每 `policy_delay` 次更新 actor 和所有 target
networks。TD target 对 terminal transition 不 bootstrap。snapshot 必须包含 online/target weights、optimizer
states、counters 和 schema version；freeze fingerprint 至少覆盖所有 tensor 的 dtype/shape/raw bytes。

## 9. Replay 与采集调度

一条 `H=8` trajectory 产生 8 transitions。禁止用少于 batch size 的 buffer 静默 update。

预声明：

```text
warm-up per role = 4 episodes = 32 transitions
N_D = 10 total Defender outer iterations
N_A = 10 attacker gradient steps per outer iteration
new collection = at least 1 fresh episode before each role update block
```

Attacker BR block：

1. capture Defender full fingerprint；
2. 用 frozen Defender + current attacker 收集 fresh trajectories 到 attacker buffer；
3. 只执行 attacker `N_A` updates；
4. verify Defender online/target/optimizer/counter fingerprint exact；
5. 在独立 BR-query seeds 上评价 initial vs adapted attacker；
6. 输出 frozen `PolicyBestResponseSnapshot`。

Defender block：

1. capture frozen BR full fingerprint；
2. 清空或 generation-tag Defender replay，避免使用旧 attacker 数据；
3. 用最终 BR attacker 重新收集 fresh trajectories；
4. 执行一次 Defender TD3 update；
5. verify Attacker online/target/optimizer/counter fingerprint exact。

这里的 `N_D` 是整个 runner 的 Defender outer-iteration count，不是每个 outer iteration 内的 update
次数。若未来采用多个 gradient steps per collection，必须单独命名为 update-to-data ratio，不能复用
`N_D` 或宣称来自 Algorithm 1。

旧 response 下的 transitions 不得用于新 BR 下的 Defender update。

## 10. 两时间尺度 runner

```text
initialize defender theta_0 and attacker phi_0
warm up role-local buffers under frozen counterpart

for outer=0..N_D-1:
  phi_BR <- train_attacker_response(freeze(theta), warm_start(phi), N_A)
  theta  <- one_td3_update(freeze(phi_BR), theta)

freeze final theta
re-solve attacker BR against final theta without defender updates
freeze both
run independent query evaluation
```

不能把 concurrent MATD3 或 joint co-learning 结果称为 E4 Stackelberg evidence。若实现 joint baseline，必须
单独命名且不参与主 Gate。

## 11. Baselines 与有限 oracle

在相同 frozen final attacker-response protocol、相同 query seeds 和相同 episode budget 下比较：

1. learned dynamic TD3 Defender；
2. random raw-action policy，每个 round 独立 uniform；
3. fixed midpoint raw action `(0,0)`；
4. fixed E2 grid policies，9 个 `(alpha,beta)` cells；
5. initial untrained TD3 Defender。

每个 baseline 都必须重新求 attacker BR，不能让 learned Defender 面对一个 attacker，而 baseline 面对另一个
固定 attacker。finite oracle 是这 9 个 fixed policies 在各自 BR 下的最佳 independent query objective。

## 12. E4.1 Gate

预声明 Gate 同时要求：

1. per-round Defender actions 在至少一个 evaluation episode 中非恒定；
2. attacker BR block 中 Defender full fingerprint exact 不变；
3. Defender block 中 Attacker BR full fingerprint exact 不变；
4. attacker adapted independent query objective 比 initial 提升 `>1e-4`，或达到预声明 policy oracle regret
   `<=1e-6` 的 plateau；
5. 至少两个 materially different Defender policies 产生不同 attacker action trajectory 或 query objective；
6. learned Defender independent query mean objective 优于 random mean `>1e-4`；
7. learned Defender 优于 fixed midpoint `>1e-4`；
8. learned Defender 到 9-cell finite oracle regret `<=0.05`；
9. learned improvement 出现在 independent query，不是 replay/training batch；
10. exact replay、dependency boundaries、canonical/full suites fresh pass。

若 empirical Gate 失败，必须报告真实失败；不得用 query seeds 选择 checkpoint、修改 reward 权重、缩放 action
范围或降低阈值。任何 redesign 需要新 spec。

## 13. 测试矩阵

单元测试：

- IPM codec endpoints/round-trip/fail-fast；
- observation hand calculation、initial mask、no future/private/oracle reads；
- Defender/Attacker reward component hand calculations；
- replay copy/freeze/capacity/sample RNG/schema；
- actor/critic shapes、bounded actions、twin target、terminal mask、policy delay、soft update；
- snapshot exact restore、unknown schema、role fingerprint；
- freeze guards detect online/target/optimizer/counter mutation。

集成测试：

- one dynamic episode exact replay and action-before-update ordering；
- Attacker 10-step block changes only attacker；
- each Defender outer step performs one update, changes only Defender and uses BR-generation-tagged data；
- final re-solved BR、support/query isolation；
- learned/random/midpoint/grid comparisons；
- two full training replays under deterministic config；
- execution packages do not import agents/Stackelberg/experiments；agents do not import execution/oracle。
