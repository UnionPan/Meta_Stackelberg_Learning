# E3.1 IPM-scale Follower Best Response Design

## 1. 文档状态与阶段边界

本文档定义第三个时间尺度的第一个可信交付：defender 先提交不可变二维 aggregation policy，
follower 在该 commitment 下只更新自己的低维 IPM scale，然后冻结 follower，在独立 query seeds
和 held-out evaluator 上验证 response objective 与行为变化。

E3.1 使用可穷举、可证伪的一维 follower action，不直接迁移历史 joint TD3。它证明严格的
Stackelberg 承诺、信息边界、support/query 隔离和 follower-only update。后续 E3.2 可以在同一
接口下替换为连续 RL solver，但不能改变本阶段冻结的物理攻击/防御语义。

## 2. 可证伪命题

E3.1 验证：

1. committed defender policy 在整个 follower training/evaluation 中 bitwise 不变；
2. follower initialization 被 clone，只有 task-local follower parameter 改变；
3. support candidate ranking 不使用 held-out loss/accuracy、真实 attacker identity oracle 或未来状态；
4. selected scale 在独立 query seeds 上优于 initial follower，或若 proxy 不对齐则明确 gate 失败；
5. 至少两个不同 commitments 产生不同 support response scores 或 selected follower behavior；
6. frozen follower evaluation 可 exact replay；
7. fixed attack 通过同一 response-oracle boundary 作为 zero-training baseline。

如果 proxy-selected scale 不能改善 independent query objective，不进入 E4 defender learning；优先重审
proxy alignment、candidate range、information set 与 defense saturation。

## 3. Stackelberg 信息结构

E3.1 使用显式 white-box commitment：

```python
FollowerKnowledge(
    knows_defender_policy=True,
    observes_current_defender_action=True,
    observes_aggregator_family=True,
    observes_defense_parameters=True,
    observes_benign_updates=True,
    observes_global_model=False,
    has_white_box_gradients=False,
)
```

选择 IPM 是因为其 E1 threat model 已允许读取 same-round benign updates，物理 action `scale` 直接、
低维且已有攻击有效性证据。E3.1 不把该信息权限外推到 BFL/DBA/Delta Reversal。

## 4. Leader Commitment

新增不可变记录：

```python
@dataclass(frozen=True)
class DefenderCommitment:
    commitment_id: str
    action: DefenseAction
    aggregation_family: str = 'clipped_trimmed_mean'
    policy_fingerprint: str
```

fingerprint 由 versioned canonical payload 计算，至少包含 family、α、β 和 codec/execution protocol。
构造、support 前后、query 前后都验证 fingerprint。commitment 不包含 mutable policy object、optimizer、
replay 或 callable closure。

第一条 response curve 使用三个预声明 commitments：

- weak/no-clip-like：`α=10, β=0`；
- norm-constrained：`α=0.1, β=0`；
- trim-constrained：`α=10, β=0.4`。

这些点来自 E2 matrix，不按 E3 query 结果选择。

## 5. Follower Policy 与 Snapshot

```python
@dataclass(frozen=True)
class IPMScalePolicySnapshot:
    scale: float
    schema_version: int

class IPMScalePolicy:
    def snapshot() -> IPMScalePolicySnapshot
    def restore(snapshot) -> None
    def act(observation) -> float
```

E3.1 policy 是单一正、finite scale。solver 必须从 caller-provided initialization clone task-local
policy；不能原地修改 shared initialization。snapshot/restore exact，未知 schema 拒绝。

candidate scales 在计划中预声明，至少包含初始值和 IPM E1 scale 3。第一版建议：

```text
0.5, 1.0, 2.0, 3.0, 5.0, 8.0
```

## 6. Support Feedback：非 Oracle Proxy

每个 support Episode 固定一个 scale 和 commitment。Episode 完成后，从 follower threat model 已允许
的信息计算逐轮 proxy：

```text
benign_mean_t = equal mean of same-round benign updates
deployed_delta_t = state_after.global_model - state_before.global_model

opposition_t = - dot(deployed_delta_t, benign_mean_t)
               / (||benign_mean_t||² + ε)

survival_t = dot(deployed_delta_t, malicious_mean_t)
             / (||malicious_mean_t||² + ε)

scale_cost = λ_scale * log1p(scale²)
proxy_scalar = opposition_t + λ_survival * survival_t - scale_cost
```

所有组件单独记录：opposition、survival、scale cost、finite/constraint violations、source protocol。
具体 `ε`、权重和 reduce 规则在实施计划中预先固定。proxy 只能读取：

- transition state-before/state-after；
- same-round benign updates（IPM capability allowed）；
- follower 自己提交的 malicious updates；
- committed public defense parameters；
- scale action。

禁止读取 held-out dataset、held-out loss/accuracy、query seeds、E2 matrix oracle metrics、未来 round 或
candidate 的 query score。support factory 不接收 oracle evaluator。

## 7. Best Response Solver

第一版使用 deterministic finite-candidate solver，不声称是 gradient RL：

```text
clone follower initialization
for scale in predeclared candidates:
  for support seed in predeclared support seeds:
    fresh initial FL snapshot
    committed defender fixed
    IPM(scale) Episode
    allowed proxy feedback
  candidate_score = mean episode proxy
select max score; exact ties choose smaller scale
restore selected scale into task-local follower
return BestResponseResult
```

每个 `(commitment, scale, support seed)` 使用 fresh dataset/model/trainer/sampler/engine/RNG。candidate
执行顺序不影响 scores/selection；新增 reverse-order property test。

结果：

```python
BestResponseResult(
    commitment,
    initial_follower_snapshot,
    adapted_follower_snapshot,
    candidate_records,
    support_seed_family,
    feedback_protocol,
    leader_fingerprint_before,
    leader_fingerprint_after,
)
```

`candidate_records` 保存完整 proxy components，不保存 query oracle。

## 8. Frozen Query Evaluation

query 使用与 support 不相交的 seed family。流程：

```text
BestResponseResult.adapted snapshot
 -> clone frozen follower
 -> for each query seed:
      fresh initial FL snapshot
      same committed defender
      fixed selected scale for entire Episode
      no follower updates / no candidate selection
      post-Episode held-out clean evaluator
 -> FrozenResponseEvaluation
```

IPM 的 query objective 是：

```text
held-out attack loss - matched clean loss
```

同时报告 clean accuracy、aggregate norms、scale、sampling 和 RNG。evaluation 不写回 follower、leader、
support records 或 normalizer。

## 9. Fixed Response Oracle

固定攻击使用相同 boundary：

```python
class ResponseOracle(Protocol):
    def solve(commitment, follower_initialization, support_factory) -> BestResponseResult

FixedIPMResponseOracle(scale)
CandidateIPMBestResponseSolver(candidates, feedback)
```

fixed oracle 返回 initial=adapted=fixed snapshot、空 update history、`training_steps=0`，仍记录 leader
fingerprint 与 protocol。这样 E4 可以冻结 learned 或 fixed response，而不分叉 environment。

## 10. Response Curve

对三个 commitments 独立：

```text
same follower initialization
same candidate scales
same support seed family
same query seed family
 -> solve follower response
 -> frozen query evaluation
```

报告：

- candidate proxy curve；
- selected scale；
- initial vs adapted query harm；
- fixed scale 0.5/1/3/8 baselines；
- leader-specific behavior difference；
- proxy rank 与 query rank 的一致/不一致；
- full clean utility。

不能用 query 结果重新选择 candidate、权重、commitment 或 checkpoint。


- `federated`、`security` 不反向导入上述高层模块。

## 12. 测试策略

### 单元

- commitment canonical fingerprint、immutability、tamper rejection；
- follower scale validation、clone、snapshot/restore/schema；
- proxy 手算、zero norm、finite、allowed-field dependency；
- solver candidate coverage、mean reduce、tie-break、reverse-order invariance；
- leader/follower freeze、factory fresh-call count；
- fixed oracle zero-training contract；
- support result 不含 query/oracle fields。

### 集成

- E1 IPM reference exact；
- support candidates matched sampling/RNG/initial model；
- support/query seed disjoint；
- selected follower frozen query replay；
- initial vs adapted independent query harm；
- three-commitment response curve；
- at least two commitments produce different response behavior/curve；
- fixed response oracle same interface；
- oracle evaluator invoked only post-Episode。

### 依赖

- `feedback`、`agents`、`stackelberg` 禁止导入 top-level evaluation/experiments where inappropriate；
- execution layers 禁止导入 environment/agent/stackelberg；
- temporary forbidden import RED / removed GREEN。

## 13. E3.1 Gate

1. commitment immutable、fingerprint stable、support/query 前后 exact；
2. caller follower initialization 不变，task-local adapted snapshot 可 replay；
3. support 只使用 capability-allowed proxy，无 oracle/query leakage；
4. all candidates × support seeds complete、matched、order invariant；
5. adapted follower 在独立 query objective 上优于 initial baseline，跨所有 declared commitments，或规范
   预先声明的 paired aggregate criterion；
6. frozen query exact replay，evaluation 不改变 follower/leader；
7. 至少两个 commitments 的 selected scale 或完整 response curve 不同；
8. fixed response oracle 通过同一 interface 且 training steps 为 0；
9. E0–E2 和 E1 IPM reference regressions继续通过；
10. dependency boundaries、canonical、full suite 通过。

若第 5 或 7 条失败，E3.1 不通过，不进入 E4。

## 14. 已知限制

- finite candidate solver 只是在声明集合上的 best response approximation；
- white-box commitment 是 worst-case training setting，不代表 black-box follower；
- 单参数 IPM 不覆盖 backdoor objective、local steps 或 mixture policy；
- proxy 与 held-out harm 可能不完全排序一致；
- 三 commitments 和少量 seeds 只用于阶段 gate；
- E3.1 不证明 defender 可学习、快速适应或 meta generalization。

## 15. 后续衔接

E3.1 通过后：

1. E3.2 可在同一 `ResponseOracle` boundary 下增加连续 actor/replay solver；
2. 冻结 follower response snapshots 和 response curve protocol；
3. E4 用 fixed task + frozen response oracle 训练 defender；
4. E4 不允许同时更新 follower；
5. E5 每 task 独立执行 follower response、support adaptation、query evaluation 和 meta update。
