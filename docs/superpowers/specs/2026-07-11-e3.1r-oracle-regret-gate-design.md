# E3.1r Oracle-Regret Best Response Gate Design

## 1. 背景与修订目的

E3.1 已实现 strict defender commitment、follower-only finite-candidate response、capability-safe
support proxy、fixed response oracle 和 independent frozen query。实现与全仓测试通过，但原科学 Gate
要求每个 defender commitment 下 adapted query harm 都比 initial scale-1 harm 严格增加 `1e-4`。

该要求在 strong clipping `(clip_radius=0.1, trim_ratio=0)` 下产生假阴性。IPM 恶意更新为
`u_s = -s b`；当 `||u_s|| > r` 时，全局 L2 clipping 得到
`clip(u_s,r) = -r b / ||b||`，正 scale `s` 被消去。声明候选 `0.5,1,2,3,5,8` 因而进入近似相同
的 deployed-response plateau。初始 scale 1 已在有限候选 oracle plateau 上，严格改善在数学上不可要求。

E3.1r 只修订科学判据和结果记录，不修改 IPM、clipping、aggregation、support proxy、candidate
集合、commitments、seeds、query evaluator 或冻结边界。

## 2. 科学命题

修订后的命题是：

1. follower adaptation 在每个声明 commitment 下达到有限候选 query oracle 的近似最优响应；
2. 对至少一个具有可辨识 response surface 的 commitment，adapted response 严格优于 initial response；
3. 不同 defender commitments 产生不同 support response curve 或 selected follower behavior；
4. plateau commitment 允许 initial 与 adapted 都达到 oracle，不把“无需改变”误判为学习失败；
5. support 仍不得读取 query oracle，oracle 只用于冻结后的离线 Gate。

本阶段证明的是声明候选集合上的 deterministic best-response approximation，不声称连续全局最优、
gradient RL convergence、Defender 可学习或 meta generalization。

## 3. 不变边界

以下内容保持 E3.1 原样：

- physical defender actions：`DefenseAction(clip_radius, trim_ratio)`；
- commitments：weak `(10,0)`、strong-clip `(0.1,0)`、trim `(10,0.4)`；
- follower initial scale：`1.0`；
- candidates：`(0.5,1,2,3,5,8)`；
- support seeds：`(701,702,703)`；query seeds：`(711,712,713)`；
- support solver 只按 capability-safe proxy 排序；
- query clean/attack matching、post-Episode evaluation、exact replay；
- leader fingerprint freeze、caller follower initialization freeze；
- fixed oracle 与 adapted response 共用同一个 frozen query execution path。

严禁根据 query 结果重新选择 adapted scale。query oracle 只计算 regret 和科学报告。

## 4. Query Oracle 与 Regret

对 commitment `c` 和声明候选集合 `S`，通过 fixed response oracle 在同一组 query seeds 上计算：

```text
H(c,s) = mean query attack harm for fixed scale s
H*(c)  = max_{s in S} H(c,s)
R(c)   = H*(c) - H(c,s_adapted)
```

其中 harm 继续定义为 matched attacked loss minus clean loss；不同 seeds 取算术平均。`R(c)` 理论上
非负；仅允许 IEEE 浮点舍入产生极小负值，Gate 比较使用绝对 tolerance。

预声明 oracle-regret tolerance：

```text
R(c) <= 1e-6
```

该 tolerance 不替代原 strict-improvement margin。对可改善性仍使用：

```text
H(c,s_adapted) - H(c,1.0) > 1e-4
```

但从“每个 commitment”改为“至少一个 commitment”。

## 5. Plateau 诊断

Gate 必须显式记录每个 commitment 的：

- 所有 candidate query harms；
- oracle harm 与 oracle scales（允许并列）；
- adapted scale、adapted harm、initial harm；
- oracle regret；
- candidate harm span；
- 是否严格改善 initial；
- 是否为 query plateau。

预声明 plateau tolerance 为 `1e-6`：

```text
query_plateau = max_s H(c,s) - min_s H(c,s) <= 1e-6
```

plateau 只是诊断标签，不自动通过 oracle-regret Gate；adapted response 仍必须落在 oracle tolerance 内。

## 6. 数据结构与职责

在 `meta_stackelberg/experiments/ipm_best_response.py` 增加不可变记录：

```python
@dataclass(frozen=True)
class CommitmentOracleRegret:
    commitment_id: str
    adapted_scale: float
    initial_harm: float
    adapted_harm: float
    oracle_harm: float
    oracle_scales: tuple[float, ...]
    oracle_regret: float
    query_harm_span: float
    query_plateau: bool
    strictly_improved: bool

@dataclass(frozen=True)
class E3OracleRegretGateResult:
    passed: bool
    commitments: tuple[CommitmentOracleRegret, ...]
    independently_improved_commitments: tuple[str, ...]
    leader_dependent_response: bool
    failed_requirements: tuple[str, ...]
```

纯函数 `evaluate_e3_oracle_regret_gate(curve_result, ...)` 只消费已经冻结的 response-curve records，
不执行 Episode、不调用 solver、不选择 follower action。它验证 fixed-query candidate coverage 与唯一性，
再计算 oracle/regret/plateau。

## 7. 修订 Gate

E3.1r 只有同时满足以下条件才通过：

1. 三个预声明 commitments 和六个 candidates 完整存在；
2. support/query seeds disjoint；
3. leader commitment 与 caller follower initialization 不变；
4. support 不读取 evaluator/query oracle；
5. frozen query exact replay；
6. fixed oracle 与 adapted response 共用 query execution；
7. 每个 commitment 的 oracle regret `<= 1e-6`；
8. 至少一个 commitment 的 adapted harm 比 initial harm严格增加 `> 1e-4`；
9. 至少两个 commitments 的 support curves 或 selected behavior 不同；
10. dependency、canonical 和 full repository suites fresh pass。

原 E3.1 的“每个 commitment 都必须严格改善”被明确废止。不得同时保留两个相互矛盾的总 Gate。

## 8. 预期现有证据

基于已经冻结、可重放的 E3.1 数据，预期：

- weak：selected 8，显著改善，接近/达到 candidate oracle；
- strong-clip：selected 0.5，candidate harms 形成 plateau，regret 接近零，无 strict improvement；
- trim：selected 8，显著改善，接近/达到 candidate oracle；
- response curves 随 commitment 改变。

这些是实施前已有的诊断证据，不允许据此修改 candidates、tolerances 或 seeds。实现必须重新 fresh
运行并报告实际值；若任一 regret 超阈值，E3.1r 仍判失败。

## 9. 测试与报告

必须增加：

- oracle/regret/并列 oracle scale 的手算单元测试；
- plateau boundary：span 等于、略低于、略高于 `1e-6`；
- 单个 strict improvement 足够、零 improvement 失败；
- candidate 缺失、重复或非 finite harm fail-fast；
- regression：strong-clip plateau 不再因“无 strict improvement”单独失败；
- regression：非 plateau 且 adapted 非 oracle 仍失败；
- 三 commitment fresh integration、exact replay、dependency、canonical/full suites；
- `docs/milestones/E3.1r-oracle-regret-gate-report.zh-CN.md` 完整列出 candidate query harms、regret、
  plateau、失败项和总结果。

## 10. 完成边界

E3.1r 通过只允许进入 E3 后续 follower 扩展或 E4 单任务 Defender 设计。它不实现 RL Defender。
若 Gate 通过，冻结 response oracle protocol、regret evaluator 和 E3 reference fingerprints；若失败，项目
继续停留在 E4 之前，必须通过新的获批设计修改 proxy、candidate action 或 commitment semantics。
