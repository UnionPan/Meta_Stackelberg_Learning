# E3.1r Oracle-Regret Best Response Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the invalid per-commitment strict-improvement E3.1 criterion with a precommitted finite-candidate oracle-regret Gate while preserving every execution, information, replay and freeze boundary.

**Architecture:** Add a pure evaluator over already-frozen response-curve records. It validates candidate coverage, computes query oracle harm/scales, regret, plateau span and strict-improvement diagnostics without running Episodes or selecting actions. The existing three-commitment runner supplies fresh fixed-query results; integration tests and a new milestone report determine the revised E3.1r result.

**Tech Stack:** Python 3.12, dataclasses, NumPy, pytest, existing deterministic PyTorch FL fixtures.

- [ ] **Step 1: Write failing aggregate requirement tests**

Cover these independent cases:

```text
all commitment regrets within tolerance + one strict improvement + leader-dependent => PASS
one regret above tolerance => FAIL "one or more follower responses exceed oracle regret tolerance"
zero strict improvements => FAIL "no commitment strictly improves over initial follower"
identical support curves and selected scales => FAIL "follower response does not depend on leader commitment"

```

The strong-clip-style plateau must not receive a bespoke exemption. It passes only because its adapted regret is within tolerance and another commitment supplies the global strict-improvement evidence.

Preserve deterministic failure ordering: coverage/validation raises immediately; scientific failures are returned in the order regret, strict improvement, leader dependence. Populate `independently_improved_commitments` in required commitment order.
