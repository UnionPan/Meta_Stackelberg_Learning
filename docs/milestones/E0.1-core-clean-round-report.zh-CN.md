# E0.1 核心契约与确定性 Clean Round 验证报告

## 1. 阶段目标

E0.1 的目标不是证明真实神经网络 FL 已收敛，而是证明新 `meta_stackelberg` 架构最底层的数据语义和模块连接方式正确：

1. 模型状态不可被跨模块意外修改；
2. client delta 和 server update 只有一种明确符号；
3. 随机状态能够 capture/restore；
4. sampler、trainer、aggregator 和 server optimizer 可以独立替换；
5. 一个 synthetic clean round 的所有中间结果可手工计算并验证；
6. canonical package 不依赖 `fl_sandbox`、`meta_sg` 或 `src`。

## 2. 权威数学语义

本阶段固定以下定义：

```text
client_delta = local_model - global_model

aggregate_delta = Aggregator(client_deltas)

global_model_next = global_model + server_lr * aggregate_delta
```

后续攻击、聚合、防御和 RL 环境必须使用相同语义，不能在模块内部重新定义正负方向。

## 3. 已实现模块

### 3.1 `meta_stackelberg.core.model_state`

提供：

- `ModelState`；
- `from_vector`；
- `model_difference`；
- `apply_delta`；
- `state_l2_norm`；
- `state_cosine`。

`ModelState` 在构造时复制输入数组并标记为只读。它拒绝空模型和非浮点 tensor，并在二元操作前检查 tensor 数量和 shape。

### 3.2 `meta_stackelberg.core.random_state`

`RandomSource` 独立持有：

- Python `random.Random`；
- NumPy `Generator`；
- Torch CPU `Generator`。

`RandomSnapshot` 保存三套 generator state。恢复 snapshot 后，三套随机数序列均可重放。

### 3.3 `meta_stackelberg.federated.types`

实现不可变边界记录：

- `ClientUpdate`；
- `RoundState`；
- `RoundRequest`；
- `RoundTransition`。

`RoundTransition` 明确分离：

```text
public_signals
private_diagnostics
```

未来 observation encoder 只能读取 `public_signals`。真实 attacker identity、真实 trigger 等 oracle 信息只能进入 `private_diagnostics`。

### 3.4 `meta_stackelberg.federated.protocols`

实现四个 runtime-checkable plug-in protocol：

```text
ClientSampler
LocalTrainer
Aggregator
ServerOptimizer
```

`RoundEngine` 只依赖这些协议，不依赖具体算法类。

### 3.5 `FedAvg`

当前 FedAvg 聚合的是 client delta，并使用 `num_examples` 加权：

```text
aggregate_delta = Σ(n_i * delta_i) / Σn_i
```

它拒绝空输入和结构不一致的 update。

### 3.6 `ServerSGD`

只负责：

```text
model + learning_rate * aggregate_delta
```

它拒绝负数、NaN 和 infinity learning rate。

### 3.7 `RoundEngine`

本阶段 engine 只执行：

```text
sample
  -> local train
  -> aggregate
  -> server step
  -> RoundTransition
```

它不负责：

- test evaluation；
- reward；
- attack；
- defense action；
- RL update；
- logging；
- checkpoint selection。

## 4. 数据流

```text
RoundRequest
  ├── task_id
  ├── RoundState_0
  ├── sample_size
  └── server_lr
        ↓
ClientSampler.sample
        ↓
sampled_clients = (0, 1)
        ↓
LocalTrainer.train(client 0)
        ↓
ClientUpdate(delta=[1,1], n=1)
        ↓
LocalTrainer.train(client 1)
        ↓
ClientUpdate(delta=[3,5], n=3)
        ↓
FedAvg.aggregate
        ↓
aggregate_delta=[2.5,4.0]
        ↓
ServerSGD.step(lr=0.5)
        ↓
global_next=[1.25,2.0]
        ↓
RoundTransition
  ├── all intermediate updates
  ├── public aggregate norm
  ├── next RNG snapshot
  └── empty private diagnostics
```

## 5. 手工预期结果

输入：

```text
global = [0, 0]

client 0:
  delta = [1, 1]
  num_examples = 1

client 1:
  delta = [3, 5]
  num_examples = 3
```

FedAvg：

```text
([1,1] * 1 + [3,5] * 3) / 4
= ([1,1] + [9,15]) / 4
= [2.5,4.0]
```

ServerSGD：

```text
[0,0] + 0.5 * [2.5,4.0]
= [1.25,2.0]
```

测试得到的实际结果与上述预期一致。

## 6. 可插拔性验证

集成测试将 `FedAvg` 替换为：

```python
class FirstUpdateAggregator:
    def aggregate(self, updates):
        return updates[0].delta.clone()
```

没有修改 `RoundEngine`。

替换后的预期：

```text
aggregate_delta = [1,1]
global_next = [0,0] + 0.5 * [1,1]
            = [0.5,0.5]
```

实际结果为 `[0.5,0.5]`。这证明 engine 依赖的是 `Aggregator` contract，而不是 FedAvg 类或其内部结构。

## 7. 确定性重放验证

`RoundEngine` 在执行开始时恢复 `RoundState.random_snapshot`，所有插件共享显式 `RandomSource`。

测试使用随机 client sampler：

1. 从相同 `RoundState` 执行第一次 round；
2. 随机源已经向前推进；
3. 再次用同一 request 执行；
4. engine 恢复 request 中的 snapshot；
5. sampled clients、aggregate delta 和 next model 与第一次完全一致。

该结果只证明当前 Python/NumPy/Torch CPU 随机源和 synthetic plugins 的重放。真实 DataLoader worker、CUDA kernel 和 stateful attack 的重放将在后续 E0/E1 单独验证。

## 9. Dependency Boundary 证据

AST import 检查会扫描 `meta_stackelberg/**/*.py`，禁止导入：

```text
fl_sandbox

```

当前检查通过。新包不使用旧实现作为运行时依赖。

## 10. 本阶段明确没有证明的内容

E0.1 没有证明：

- MNIST/CIFAR clean FL 收敛；
- PyTorch local trainer 正确；
- non-IID partition 正确；
- robust aggregation 正确；
- 攻击有效；
- 防御动作可控；
- RL agent 能学习；
- Meta-SG 能快速适应。

这些结论必须由后续阶段各自提供证据，不能从 synthetic round tests 外推。

## 11. E0.1 Gate 结论

E0.1 通过，依据是：

- update 数学与手工结果一致；
- 数据记录不可变；
- public/private 数据分离；
- RNG 能重放；
- aggregator 可替换；
- canonical dependency guard 通过；
- canonical 和 legacy 测试全部通过。

## 12. E0.2 前置条件

下一阶段实现真实 clean FL 组件：

1. `DatasetProvider` 和 deterministic partition；
2. canonical model registry；
3. PyTorch `LocalTrainer`；
4. client sampling；
5. sample-mean clean evaluator；
6. 小型 synthetic classification convergence；
7. MNIST smoke run，但不把下载数据作为默认单元测试前提。

E0.2 必须继续使用本阶段的 `ModelState`、`ClientUpdate`、protocol 和 `RoundEngine`，不能另建第二套权重或 runner 表示。
