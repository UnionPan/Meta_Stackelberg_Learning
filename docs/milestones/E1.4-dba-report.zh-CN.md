# E1.4 DBA 分布式后门攻击里程碑报告

## 1. 研究问题与范围

E1.4 回答一个受限问题：在固定恶意客户端各自只使用一个不同 sub-trigger 进行真实 poisoned local SGD 时，正常联邦聚合能否在独立 held-out 数据上形成组合 full trigger 的 source→target 激活；同时，组合效果是否能与 matched no-op 基线作因果对照。

本阶段实现的是固定 DBA（Distributed Backdoor Attack）执行与有效性证据，不是攻击策略学习，也不包含 trigger 隐蔽性优化、自适应防御绕过、攻击者 Best Response 或防御方训练。结果只说明当前受控 fixture 中的实现语义与现象。

## 2. Threat model 与 capability 边界

DBA generator 声明 `LOCAL_MODEL_CAPABILITIES`：

```text
needs_global_model = True
needs_local_data   = True
```

攻击者可读取当前 global model，并只能通过 scoped trainer 使用其被授权恶意客户端的本地 poisoned dataset。它不观察同轮 benign updates，不读取其他客户端数据、held-out oracle、ASR、private diagnostics 或未来状态。攻击执行只生成正常本地训练得到的 delta；held-out 指标在 Episode 完成后由独立 evaluator 计算，不反馈给攻击者。

## 3. 模块与数据流

- `security/data/trigger.py`：运行时可检查的 `ImageTrigger` 协议与不可变 `CompositeTrigger`。
- `security/data/poisoning.py`：接受通用 image trigger 的确定性 `SourceTargetPoisonedDataset`。
- `security/attacks/dba.py`：`DistributedTriggerPlan` 与 trainer-backed `DistributedBackdoorUpdateGenerator`。
- `evaluation/targeted.py`：与 DBA 模块解耦的 held-out source-only evaluator。
- `integration/test_dba_attack_validity.py`：三 seed matched 因果实验。

训练与评估数据流为：

```text
fixed malicious client id
        ↓ DistributedTriggerPlan.trigger_for(client_id)
该 client 唯一绑定的 sub-trigger
        ↓ SourceTargetPoisonedDataset
固定选择真实 source 样本，应用 local sub-trigger 并改标为 target
        ↓ exact built-in TorchLocalTrainer（真实 local SGD）
        ↓ DistributedBackdoorUpdateGenerator
保留真实 delta / sample count，附加 DBA assignment metadata
        ↓ AttackRoundEngine（无 DBA 专用分支）
FedAvg → ServerSGD → final model

independent held-out clean dataset
        ↓ 只筛选真实标签为 source 的样本
分别应用每个 sub-trigger，或按序应用 CompositeTrigger(full trigger)
        ↓
预测为 target 的数量 / held-out true-source 数量 = ASR
```

关键分离是：客户端本地训练只见其固定 sub-trigger；组合 full trigger 只存在于 held-out evaluator。任何客户端都不使用 full trigger 训练。

## 4. 接口与不变量

1. `DistributedTriggerPlan` 至少包含两个在构造时经标量 equality 判定为 value-distinct 的 sub-trigger；client ID 与索引必须是非布尔、非负整数，所有 scoped attackers 恰好有合法 assignment，且不存在未使用 sub-trigger。普通的（包括可变、不可哈希的）`ImageTrigger` 协议实现可以使用；plan 不承诺递归冻结 trigger 内部状态。
2. plan 将调用方传入的 sub-trigger 序列复制为 tuple、attacker IDs 规范化为 frozenset，并将 assignment 复制后通过稳定的只读 mapping 暴露；因此容器和 assignment 不会随原始 list/dict 的修改而变化。plan 可 deepcopy/pickle 往返并保持该只读 mapping 与值相等语义，但不保证自身或任意第三方 trigger 可哈希，也不保证第三方 trigger 后续内部修改不会改变行为。
3. `CompositeTrigger` 按声明顺序应用组件，每步都要求 tensor 的 shape、dtype、device 不变，并保证输入不被修改。
4. generator 保留调用方提供的 exact shared `ScopedLocalTrainer`、其 exact built-in `TorchLocalTrainer`，以及其中的原始 dataset 对象，不复制 poison view 或底层 clean dataset；`dataset.trigger` 必须与 plan 分配的 trigger 是同一对象。构造时逐客户端复核 exact 类型、scope、source/target/fraction、trigger identity，并记录 poison view、clean dataset identity 以及 `poisoned_indices`/`eligible_count` baseline。
5. 每次 `craft` 在训练或消费 RNG 之前再次复核 exact trainer/dataset 类型、完整 scope、当前客户端的配置与 trigger identity、poison view/clean dataset identity，以及 `poisoned_indices`/`eligible_count` baseline；失败时拒绝训练且不消费传入 RNG。这是 fail-closed 的浅层结构防护，不会深检底层 clean tensor 内容。调用方必须把 trainer、plan、trigger、poison view、clean dataset 及其数据内容视为任务期间固定配置；直接原地修改 clean tensor 等共享状态仍可能改变训练语义。
6. craft 后保留 trainer 产生的真实 delta 与 `num_examples`，只将更新标为 malicious 并加入 `attack_type='dba'`、类别、fraction、sub-trigger index/count 元数据。

这里的 pickle/deepcopy 往返仅是当前 Python 对象协议测试，不是通用 wire format 或跨实现序列化承诺。

## 5. TDD 与独立审查摘要

实现按 failing test → 最小实现 → 回归的顺序覆盖 trigger composition、plan、generator 和 matched Episode。独立只读审查聚焦 assignment correctness、full-trigger denominator、local/full trigger separation、数据所有权、RNG matching，以及 DBA 是否错误退化为单 trigger BFL。

审查与回归测试推动的主要修复包括：

- 删除对 sub-trigger 深层不可变/可哈希的过强限制，保留 `ImageTrigger` 协议兼容性；构造时用标量 equality 检查 value-distinct，非标量结果或 equality 异常统一 fail closed；
- 要求 exact trainer/dataset 类型，拒绝通过 subclass 改写 copy/训练语义；
- 保留 exact shared trainer/dataset，不要求 deepcopy；以构造 baseline 和每次 craft 前的 identity/config/state 复核检测替换或配置漂移，同时明确不深检 clean tensor 内容；
- 补齐非法 scoped client、错误 assignment/config/trigger、布尔 fraction、组件输出不兼容等失败路径；
- 用 regression tests 与代码审查共同确认 full trigger 只由 evaluator 使用、source-only 分母为 60，且 `security` 不反向依赖 `evaluation`。

最终没有为 DBA 修改 `AttackRoundEngine`；generator 继续通过已有 `MaliciousUpdateGenerator` per-client contract 可替换接入。

## 6. Matched 实验设置

```text
train examples:       120
held-out examples:    120（独立 TensorDataset，level offset 不同）
image shape:          1×8×8
model:                Flatten + Linear(64,2)，相同零初始化 snapshot
classes:              source=0, target=1
sub-triggers:         3 个互不重叠的 bottom-row 2×2 patch
clients:              6
malicious clients:    {0,1,2}，各固定绑定一个 sub-trigger
sample size:          4 / round
horizon:              8 FL rounds
local SGD lr:          0.08
local epochs:         2
batch size:            8
aggregator:            sample-weighted FedAvg
server optimizer:      ServerSGD
seeds:                 601, 602, 603
```

四个 matched 分支为 `clean`、`identity`、`DBA fraction=0` 和 `DBA strong (fraction=1)`。同一 seed 共享初始模型、client sampling、训练随机源与 FL 配置。每个 sub/full ASR 的 held-out true-source 分母均为 60，clean accuracy 分母为 120。

集成测试还显式验证本 fixture 的空间与数据证据：恰好三个 `2×2` patch；每个 patch 的作用 mask 非空且两两不相交；full trigger 的三个组件按顺序逐项与 `SUB_TRIGGERS` 保持 object identity，full 输出等于依序应用三组件，变化 mask 等于三 mask 的并集，且各 mask 上的值与对应组件一致。train 与 held-out 是不同对象，对应 tensors 的 storage 均不别名，images 内容不同；所有 targeted 与 clean evaluators 均绑定 held-out 对象。这里验证的是本实验的三个 disjoint patch，不是 `DistributedTriggerPlan` 通用 API 的空间不相交保证。

## 7. 实际结果

| Seed | No-op full ASR | Strong full ASR | Strong sub-0 ASR | Strong sub-1 ASR | Strong sub-2 ASR | Identity clean loss | Strong clean loss | Identity / strong clean acc. | 每轮恶意客户端数 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|:---|
| 601 | 0.0000 | 1.0000 | 0.2167 | 0.2167 | 0.2667 | 0.0022122069 | 0.0215799781 | 1.0 / 1.0 | 2,2,2,3,2,2,1,1 |
| 602 | 0.0000 | 1.0000 | 0.6500 | 0.8500 | 0.9167 | 0.0021479519 | 0.0452095097 | 1.0 / 1.0 | 2,2,2,2,2,3,2,2 |
| 603 | 0.0000 | 1.0000 | 0.9500 | 0.3333 | 1.0000 | 0.0021735198 | 0.0448833883 | 1.0 / 1.0 | 2,2,3,1,2,3,2,2 |

表中 no-op 指 matched identity；clean、identity 与 DBA fraction=0 的最终 clean/sub/full metrics 完全相同。三者还逐轮满足 sampled clients、aggregate delta、global model 与 parent RNG snapshot exact equality。strong 分支与它们逐轮 sampled clients 和 parent RNG snapshot 相同。identity、fraction=0 与 strong 每轮记录的 malicious update 数和 private diagnostic count 均精确等于 sampled clients 与 `{0,1,2}` 的交集，且每轮至少采到一个恶意客户端；逐 seed/轮恶意客户端数就是表中所列序列。因此，当前 exact matching 支持的因果范围仅是：在固定代码、fixture、seed、初始状态、采样与 RNG 轨迹下，观察到的模型差异可归因于把恶意客户端的 local dataset 从 no-op 改为对应 sub-trigger 的 fraction=1 poisoned view。它不识别对其他数据、模型、seed 或威胁模型的平均因果效应。

strong full ASR 相对 no-op 在三 seed 均由 0 升至 1，clean accuracy 均保持 1，但 clean loss 明显上升；因此不能写成“无 utility 代价”。

组合增益定义为：

```text
strong full-trigger ASR - max(strong single-sub-trigger ASR)
```

逐 seed 为 `0.7333 / 0.0833 / 0.0000`，总和为 `0.8167`。这证明 full trigger 在每个 seed 至少不弱于最强单 sub-trigger，且 sweep 中存在严格组合优势；它不证明每个 seed 都存在严格 synergy。seed 603 的 sub-2 已达到 full-trigger ASR=1.0，是明确的单 sub-trigger 饱和反例。

## 9. 局限

- 数据是高度合成、线性可分的 `1×8×8` toy fixture，不能代表自然图像或真实联邦异质性。
- 只有固定三个 seeds（601–603），不足以估计方差、置信区间或总体成功概率。
- strong full-trigger ASR 三 seed 均饱和到 1，无法比较更高强度，也可能掩盖组合差异。
- seed 603 中单个 sub-trigger 已等于 full trigger，故不能宣称组合在每个 seed 都严格优于单组件。
- generator 共享调用方 trainer/dataset，仅对已声明的 identity/config/poison-view baseline fail closed，不深检 clean tensor；任务配置与共享数据必须由调用方保持固定。
- 项目 `.venv` 在本次环境中失效；上述测试验证改用 `/Users/antik/anaconda3/bin/python`，因此证据限定于该替代解释器环境。
- 本实验没有现实世界鲁棒性、隐蔽性或跨模型迁移证据，也不是 defender 训练结果。
