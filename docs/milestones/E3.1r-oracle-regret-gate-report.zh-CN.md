# E3.1r Oracle-Regret Best Response Gate 里程碑报告

## 1. 修订结论

E3.1r 按获批规范只修订离线科学 Gate，不修改 IPM、clipping、aggregation、support proxy、candidate
solver、commitments、seeds 或 query execution。fresh 三 commitment 结果满足：每个 adapted response
均达到声明六候选 query oracle（regret `0 <= 1e-6`），weak 与 trim 相比 initial scale 1 严格改善，
strong-clip 被正确识别为 query plateau。因此修订总 Gate：`passed=True`。

原 E3.1 报告的 FAILED 仍是当时判据的真实结果；E3.1r 不回写历史，而是用新设计明确废止逻辑上
无效的“每个 commitment 必须严格改善”要求。

## 2. 不变执行与信息边界

- Defender commitment：versioned canonical fingerprint，support/query 前后不变；
- follower：caller initialization clone，只有 task-local snapshot 改变；
- support：只读 same-round benign/malicious updates 与 deployed model difference，不构造 evaluator；
- adapted action：只由 support proxy 选择，query oracle 不进入 solver；
- query：support/query seeds disjoint，matched clean/attack，post-Episode held-out loss；
- fixed oracle 与 adapted response 使用同一个 `frozen-ipm-query-v1` execution；
- Gate evaluator 是纯函数，只消费已冻结 records，不运行 Episode、不选择 action。

## 6. Oracle Regret 与 Plateau

| commitment | adapted scale | initial harm | adapted/oracle harm | oracle scales | regret | span | plateau | strict improve |
|---|---:|---:|---:|---|---:|---:|:---:|:---:|
| weak | 8 | 0.4746971545 | 77.5816017069 | `8` | 0 | 77.4735568821 | 否 | 是 |
| strong-clip | 0.5 | 0.5291529695 | 0.5291529695 | `0.5,1,2,8` | 0 | 7.9472859404e-09 | 是 | 否 |
| trim | 8 | 0.3401030704 | 70.3124160732 | `8` | 0 | 70.2232186536 | 否 | 是 |

strong-clip 的 scale 在 L2 clipping 后失去幅值可辨识性。initial 和 adapted 都位于有限候选 oracle
plateau；“无 strict improvement”在此不是 best-response 失败。它仍必须满足 regret tolerance，不能仅凭
plateau 标签自动通过。

## 9. 限制与完成边界

- oracle 只覆盖六个离散 scales，不证明连续全局最优；
- 只有 IPM family、三个 commitments、三个 query seeds，无置信区间；
- strong-clipping plateau 不证明所有 adaptive attacks 都被防住；
- 本阶段不是 gradient RL convergence，也不证明 Defender 可学习或 meta generalization。

E3.1r 通过后可以开始 E4 单任务 RL Defender 的独立设计。E3.1r 本身未实现 RL Defender；E4 必须冻结
follower response/oracle，不允许同时更新双方后声称 strict Stackelberg learning。
