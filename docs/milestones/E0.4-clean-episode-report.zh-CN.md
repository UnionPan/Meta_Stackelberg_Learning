# E0.4 Clean Episode 与 RNG 隔离报告

日期：2026-07-11
分支：`codex/m0-baseline`

## 1. 阶段假设

E0.1–E0.3 已证明 clean FL 单轮数学正确，并在测试循环中完成多轮学习与 checkpoint 恢复。E0.4 要证明：H 个 FL rounds 可以由正式、无学习职责的 Episode 模块编排；同时，sampling 与各客户端内部随机消费互不干扰，使未来 clean/attack matched comparison 只改变攻击变量。

E0.4 成功不代表攻击、防御、Best Response 或 Meta-SG 已经成立。

## 2. 模块和接口

### `RandomSource.spawn()`

parent NumPy RNG 每次只产生一个 child seed。child 拥有独立的 Python、NumPy 和 Torch generators；child 内部消费多少随机数，都不改变 parent 的后续状态。

### `RoundExecutor`

```python
class RoundExecutor(Protocol):
    def run_round(
        self,
        request: RoundRequest,
        rng: RandomSource,
    ) -> RoundTransition: ...
```

`RoundEngine` 满足这个协议；未来 `AttackRoundEngine` 可以通过同一接口替换，不需要修改 Episode。

### `EpisodeSpec`

固定：

- task id；
- horizon；
- 每轮 sample size；
- server learning rate；
- initial `RoundState`。

### `FederatedTrajectory`

保存 initial state、按顺序排列的 transitions 和 final state。构造时会：

- 将输入 transitions 复制为 tuple；
- 拒绝空 task 和空 trajectory；
- 验证第一步 state、相邻 state、task id 和 final state；
- 比较模型参数、RNG snapshot 和 component states。

### `EpisodeRunner`

只负责连续调用 `RoundExecutor`。它不依赖 evaluator、reward、agent、replay、TensorBoard 或 checkpoint selection。

## 3. Parent/Child RNG 数据流

```text
RoundState_t.random_snapshot
        ↓ restore parent RNG
parent.spawn()
        ↓
sampling child RNG
        ↓
sample ordered clients (c₁, ..., cₘ)
        ↓
parent.spawn() × m
        ↓
client child RNG₁ ... client child RNGₘ
        ↓
each local trainer consumes only its child
        ↓
capture parent RNG
        ↓
RoundState_{t+1}.random_snapshot
```

每轮 parent 固定消费 `1 + sampled_client_count` 个 child seeds。攻击者以后可以在 malicious client child 中执行额外随机操作，但不能改变下一轮 sampling child。

## 4. Episode 数据流

```text
EpisodeSpec(task ξ, horizon H, initial state)
    ↓
RoundRequest₀ → RoundExecutor → RoundTransition₀
    ↓ state_after
RoundRequest₁ → RoundExecutor → RoundTransition₁
    ↓
...
    ↓
RoundRequest_{H-1} → RoundExecutor → RoundTransition_{H-1}
    ↓
FederatedTrajectory
```

Episode 只改变 deployed FL state。held-out evaluation 在 Episode 外部完成，因此 oracle metric 不会成为下一轮输入。

## 5. 预期结果

### RNG 单模块

- parent snapshot 恢复后，spawn 的 child 三套 RNG 完全重放；
- child 内进行 0 次或 100 次随机消费，parent 的下一个 child 不变；
- local trainer 随机消费不同，不改变连续 rounds 的 sampled clients 或 parent snapshot。

### Episode 单模块

- horizon 精确等于 transition 数量；
- Episode 与直接逐轮调用得到同一 trajectory；
- 任意 `RoundExecutor` 插件只需满足协议；
- task/state/final-state 不连续立即失败。

### 纵向实验

- 8-round real PyTorch clean Episode 能降低 held-out loss；
- 第 3 轮保存、加载、重建组件后的 5-round suffix 与 uninterrupted trajectory 完全一致；
- equality 不只比较最终参数，还逐轮比较 client updates、aggregate delta、states、signals 和 RNG snapshot。

## 9. 已知限制与 Gate 结论

已知限制：

- 当前 Episode 只记录 federated transitions，不包含 observation、action 或 reward；这些属于后续 game environment；
- 当前只验证 clean `RoundEngine`，尚无 canonical `AttackRoundEngine`；
- RNG child seeds 由 parent NumPy stream 顺序派生，matched engines 必须保持每轮相同的 sampled slot 数；
- checkpoint 仍只保存浮点训练参数，不包含未定义聚合语义的 model buffers。

E0.4 gate 通过条件为：正式 Episode、RNG 隔离、manual equivalence、完整 suffix replay、插件 contract 和 clean convergence 全部成立。独立审查无未解决问题，最终 canonical 90 项与全仓相关 410 项测试全部通过，因此本阶段判定通过。

## 10. E1 前置条件

E1 `AttackRoundEngine` 必须复用以下协议：

```text
same EpisodeRunner
+ same initial RoundState
+ same parent spawn count
+ same sampling child
+ same sampled-order client children
```

clean/no-op/attack paired comparison 必须先验证 sampled history 和 parent RNG snapshot 一致，再计算 attack harm。E1 将新增 malicious population、capability validation、identity generator、delta reversal 和真实 backdoor local training，但不能把 oracle ASR 接入 Episode 或 attack generator。
