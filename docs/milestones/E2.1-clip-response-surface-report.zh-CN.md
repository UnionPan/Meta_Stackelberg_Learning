# E2.1 Clip Radius 防御响应面里程碑报告

## 1. 阶段假设

E0 已证明 clean FL round 与 Episode 的数学、RNG 和 replay 语义，E1 已分别验证 fixed untargeted、BFL、IPM/LMP 与 DBA。E2.1 固定 E1.1 的 Delta Reversal + FedAvg task，只回答：单一连续 `clip_radius` 动作能否在不改变客户端训练与随机流的情况下形成可辨识的聚合和 held-out 指标响应面。

本阶段不训练 defender/attacker，不实现 Best Response，不选择 observation，也不把当前结果解释为通用鲁棒性。

## 2. 模块和接口

- `DefenseAction(clip_radius)`：不可变、有限正数的物理动作；
- `ClipRadiusActionCodec(min_radius, max_radius)`：`[-1, 1]` 与物理半径闭区间之间的一维线性映射；
- `ClippedAggregator(base, clip_radius)`：逐 client 全模型 L2 clipping 后委托现有 `Aggregator`；
- `ClippingSummary`：无状态汇总 client count、裁剪比例与裁剪前 norm 范围；
- `RawClipObservation`：Episode 后的模型、指标、采样、RNG 和逐轮聚合记录；
- `evaluate_clip_response_surface`：从独立 factory 构造每个 seed × radius × branch；
- `ClipControllabilityGate`：使用预先固定阈值判断 response surface。

联邦核心的 `RoundRequest`、`RoundEngine`、`AttackRoundEngine`、`EpisodeRunner` 和 `Aggregator` protocol 均未增加 defense-specific branch。

## 3. 数据流

```text
normalized action
 -> ClipRadiusActionCodec
 -> DefenseAction
 -> ClippedAggregator(FedAvg)
 -> existing RoundEngine / AttackRoundEngine
 -> EpisodeRunner (8 rounds)
 -> final model + held-out evaluator
 -> RawClipObservation
 -> matched clean/attack comparison
 -> ClipResponseSurface + offline gate
```

clipping operator 只读取提交给聚合器的 updates。held-out evaluator 在 Episode 完成后运行；`attack_harm` 只在 clean/attack 两个 raw observations 都生成后计算，不进入任一 Episode。

## 5. 预期结果与失败解释

成功预期：较小 radius 限制攻击 delta 的同时也限制 benign learning，形成 clean utility、attack harm 与 defense cost 的可解释 trade-off；response surface 的 aggregate 与 held-out metric 均非平坦。

失败解释：若 aggregate 平坦，优先检查 action range、全模型 norm 计算与聚合注入；若 aggregate 非平坦而 held-out metric 平坦，优先检查 horizon、fixture 灵敏度和 evaluator；任何一种失败都不进入 RL。

## 7. 单元测试证据

- action：frozen、finite positive、bool/type rejection；
- codec：端点、round-trip、shape/dtype/finite/range、物理范围；
- clipping：多 tensor 联合 L2 手算、zero/boundary、sample weighting、dtype/metadata、输入不变、permutation、no-clip exact；
- summary：无状态、裁剪比例与 norm 统计；
- response records：finite、immutable model copy、坐标与长度；
- runner：canonical order、fresh factory、matched sampling/RNG、成本和 harm 的 post-Episode 计算；
- gate：`1e-6` / `1e-4` 的严格阈值行为。

fresh focused defense suite：53 项通过。

## 8. 集成与依赖证据

- 三 seed × 五 radius × clean/attack 共 30 个独立 Episode；
- 完整 surface 连续运行两次，metrics、aggregate norms、clipping summaries、sampled clients、final model 与 RNG exact；
- 每个 radius 的 clean/attack sampled clients 与 final parent RNG exact；
- reference radius 逐 seed、逐 branch 与原生 FedAvg 的 aggregate norms、final model、metrics、sampling 和 RNG exact；
- dependency tests 通过真实注入 forbidden import 的 RED，再删除后 GREEN；
- `security/defenses` 禁止导入 oracle/experiments，execution layers 禁止反向导入 experiment orchestration。

fresh canonical：314 项通过。fresh 全仓：634 项通过。

## 9. 与基线的差异

原 E1.1 只使用固定 FedAvg 并证明 Delta Reversal harm。E2.1 未修改攻击、trainer、sampler、Episode 或 evaluator；唯一实验变量是注入现有 Aggregator protocol 的 physical clip radius。`radius=10` 的 exact baseline 证明新 defense infrastructure 在 no-clip 区域不改变基线行为。

## 10. 已知限制

- 三个固定 seeds 仅用于阶段 gate，不估计总体方差或置信区间；
- 当前只覆盖 Delta Reversal + FedAvg，不证明对 BFL、IPM/LMP、DBA 或其他聚合器有效；
- 强 clipping 同时抑制 benign learning，不能仅按 attack harm 选择动作；
- 本阶段的 `defense_cost=log(reference/radius)` 只用于响应面解释，尚未作为 RL reward；
- `.venv` 在当前 worktree 不可用，验证使用上述 Anaconda Python；
- 没有 defender policy、follower Best Response、support/query adaptation 或 meta update 证据。
