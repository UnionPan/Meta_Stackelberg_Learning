# E1.3 IPM / LMP 全局模型投毒里程碑报告

## 1. 本阶段目标

E1.3 迁移两种依赖“同轮参考更新”的固定全局模型投毒攻击：

- IPM（Inner Product Manipulation）：沿 benign mean update 的反方向提交恶意更新；
- LMP（Local Model Poisoning）：迁移 `fl_sandbox/attacks/lmp.py` 的 `Median_craft_real` 风格坐标构造，专门在 CoordinateMedian 场景验证。

本阶段不把二者包装成普通逐客户端攻击，因为它们在构造更新前需要观察同轮 benign updates。为此新增 round-level attack contract 与确定性 two-pass round engine。

## 2. 第一性原理与 threat model

### IPM

令同轮可观察的 benign client deltas 为：

```text
δ̄_b = mean(δ_b1, ..., δ_bn)
```

IPM 对每个恶意客户端提交：

```text
δ_m = -γ · δ̄_b,  γ > 0
```

因此非零参考更新必须满足：

```text
<δ_m, δ̄_b> = -γ ||δ̄_b||² < 0
```

IPM 声明 `observes_benign_updates=True`，但不需要 global model 或 local data。

### LMP

LMP 需要：

- 当前 global model；
- 同轮 benign local models（由 `global + benign delta` 恢复）；
- 每个恶意 slot 的显式 RNG。

它先计算 coordinate median 相对 global model 的方向，再在 benign coordinate min/max 的反方向区间随机构造恶意 local model。方向为零时沿用迁移变体语义，将该 local-model coordinate 设为零。最后转换回 canonical delta。

LMP 声明 `needs_global_model=True`、`observes_benign_updates=True`，不读取 held-out oracle、private diagnostics 或其他客户端数据集。

## 3. 模块划分

- `security/types.py`：`RoundAttackContext`，只承载声明允许的研究证据。

- `security/engine/attack_round_engine.py`：兼容旧 per-client attacks 的 two-pass 执行。

- `integration/test_ipm_lmp_attack_validity.py`：matched causal experiments。

## 4. Two-pass round 数据流

```text
RoundState.random_snapshot
        ↓ restore parent RNG once
sample client IDs + spawn one child RNG per sampled slot
        ↓
Pass 1: 只训练 sampled benign slots
        ↓
capability-cropped RoundAttackContext
  - needs_global_model=False → global_model=None
  - observes_benign_updates=False → benign_updates=()
        ↓
Pass 2: round generator 为 sampled malicious slots 构造更新
        ↓
按原 sampled client order 重建 ordered_updates
        ↓
FedAvg 或 CoordinateMedian → ServerSGD → RoundTransition
```

每个 slot 的 child RNG 在采样时已经固定，所以 benign-first 的计算顺序不改变 parent RNG trajectory。最终 aggregator 仍消费原 sampled order，避免浮点求和顺序和 order-sensitive aggregator 发生变化。

round generator 必须通过 `malicious_client_ids` 获得本轮需要构造更新的 selected malicious IDs；但它不接收 `private_diagnostics` mapping 或其中的统计字段。`private_diagnostics` 只在攻击更新构造完成后附加到 transition。

## 5. Capability 强制执行

独立审查发现，初版虽然校验 capability，却仍向所有 round generators 传递 global model 与 benign updates。这会让虚假 capability 声明绕过 threat model。

修复后 engine 按 capability 裁剪 context：

```text
未声明 needs_global_model       → global_model is None
未声明 observes_benign_updates → benign_updates == ()
```

回归测试使用 `AttackCapabilities()` 和 `AttackKnowledge()` 的最小 generator，证明它无法看到这两类证据。

## 6. 单模块验证

### Round contract / engine

- 恶意 slot 位于 benign slot 之前时，仍能获得完整的同轮 benign references；
- round generator 返回数量、client ID、malicious flag 与最终结构均被验证；
- clean 与 round-identity 的 aggregate、model、sampling、parent RNG 逐轮完全一致；
- 原 identity、delta reversal、BFL per-client generator 路径保持兼容。

### IPM

- 多 tensor layer、float32/float64 的手工均值与反向缩放；
- 非法 scale、空 reference、RNG 数量、sample count、结构/dtype 错误；
- 每个恶意客户端获得独立只读 ModelState；
- matched Episode 每个 malicious update 与 benign mean 的内积严格为负。

### LMP

- positive/negative/zero median directions；
- positive/negative coordinate ranges；
- 显式 child RNG 的 exact replay；
- 不同恶意 slot 不共享数组或 RNG 结果；
- multi-layer reconstruction；
- scale、reference、RNG 与 sample-count 验证。

### CoordinateMedian

- 每个 coordinate 独立求 median；
- 多层与 dtype 保持；
- 空输入、结构和 dtype mismatch 拒绝。

## 7. Matched 实验配置

```text
train examples:       120
held-out examples:    120（独立 offset）
model:                Linear(2,2)
clients:              6
malicious population: {0,1,2}
sample size:          4 / round
horizon:              8 rounds
local SGD lr:         0.2
local epochs:         1
batch size:           8
server optimizer:     ServerSGD
IPM scale:            3.0
LMP scale:            5.0
seeds:                501, 502, 503
```

比较组：

```text
FedAvg:           clean / round-identity / IPM
CoordinateMedian: clean / round-identity / LMP
```

LMP 结论只针对 CoordinateMedian，不从该实验推断其对 FedAvg、Krum 或其他防御聚合器的效果。

## 8. 实际结果

### IPM / FedAvg

| Seed | Identity loss | IPM loss | Identity acc. | IPM acc. | Mean malicious norm | Mean aggregate norm | 最大恶意-参考内积 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 501 | 0.0314509423 | 21.1848705292 | 1.0 | 0.0 | 3.3871607780 | 1.0276738405 | -0.8641977906 |
| 502 | 0.0310745439 | 24.3655170441 | 1.0 | 0.0 | 3.5465650558 | 1.1808987856 | -0.8447236419 |
| 503 | 0.0314916898 | 28.3842475891 | 1.0 | 0.0 | 3.6572692394 | 1.3761628866 | -0.8523967862 |

表中“最大恶意-参考内积”是在所有 attacked rounds / malicious slots 中最接近零的值，仍严格小于零。因此不仅 final loss 变差，IPM 的逐轮算子语义也成立。

### LMP / CoordinateMedian

| Seed | Identity loss | LMP loss | Loss increase | Identity acc. | LMP acc. | Mean malicious norm | Mean aggregate norm |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 501 | 0.0313845357 | 0.1114874348 | 0.0801028991 | 1.0 | 1.0 | 0.3681135476 | 0.2375109792 |
| 502 | 0.0310765537 | 0.1288060978 | 0.0977295441 | 1.0 | 1.0 | 0.3190170527 | 0.1734897792 |
| 503 | 0.0314210417 | 0.1093830232 | 0.0779619815 | 1.0 | 1.0 | 0.4205104709 | 0.2301513851 |

LMP 在三个 seed 上均提高 held-out loss，但 accuracy 尚未跨过决策边界。因此本阶段只证明“在该受控任务上改变 CoordinateMedian 结果并降低置信度/margin”，不宣称所有 seed 均造成分类错误。

每轮 sampled malicious client count：

```text
seed 501: 1,2,2,1,3,2,3,1
seed 502: 2,2,2,1,2,2,3,2
seed 503: 2,2,3,3,2,2,2,1
```

同一 seed 的 identity、IPM/LMP 具有相同 sampling 与 parent RNG trajectories。clean 与 round-identity 在各自聚合器下逐轮 aggregate/model 和最终 metrics 完全相同。

## 9. 预期与 Gate 对照

- 显式 benign-update observation capability：已覆盖；
- capability-cropped evidence：已覆盖；

## 10. 局限与下一步

- 当前实验仍是线性可分合成任务，目的是验证算法语义与证据链，不代表真实数据集效果量。
- IPM/LMP 都假设可以观察同轮 benign updates，这是较强攻击知识，必须由 task ξ 显式允许。
- LMP 固定为迁移的 `median_craft_real` 变体；不能与项目中曾出现的“简单放大 benign mean 反方向”同名 stub 混用。
- 当前只实现 CoordinateMedian；Krum、trimmed mean 等聚合器需各自单独设计与验证。
- 下一阶段 E1.4 复用 E1.2 的 trigger、poisoned dataset 与 ASR oracle，迁移 DBA 的 per-attacker sub-trigger 分工。
