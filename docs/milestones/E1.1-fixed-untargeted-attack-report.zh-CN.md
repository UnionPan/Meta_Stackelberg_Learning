# E1.1 Fixed Untargeted Attack Validity 报告

日期：2026-07-11
分支：`codex/m0-baseline`

## 1. 阶段假设

E0 已证明 clean FL round、Episode、checkpoint 与 RNG replay 正确。E1.1 要验证的不是“所有攻击都有效”，而是以下更窄、可证伪的命题：

> 在声明的 synthetic binary-classification fixture、固定 malicious population 和三个 sampling seeds 上，一个不观察其他客户端 update、只反转自身 honest local update 的 fixed untargeted attack，能够在保持 matched sampling/RNG 条件不变时增加 held-out clean loss。

E1.1 同时要证明攻击基础设施本身没有引入 harm：identity/no-op generator 必须与 clean FL 完全等价。

## 2. 为什么第一种攻击选择 Delta Reversal

Delta Reversal 是攻击框架的校准攻击，不是统一攻击公式。它具备四个适合第一阶段的性质：

- 只使用恶意客户端自己的 local data 和 global model；
- 不需要观察本轮 benign updates；
- 不使用 held-out/oracle 数据；
- attack budget 与输出 delta 可以手工计算。

后续 backdoor、IPM、ALIE、LMP 和 adaptive attacker 会通过同一 `MaliciousUpdateGenerator` protocol 实现，但各自拥有不同的数据流、capability、参数和评价指标。

## 3. 攻击数学语义

恶意客户端先执行与 honest client 相同的本地训练：

```text
base_delta = local_model - global_model
```

然后执行：

```text
crafted_delta(b) = (1 - b) × base_delta
```

对应：

| budget `b` | 输出 | 含义 |
|---:|---:|---|
| 0 | `base_delta` | identity/no-op |
| 1 | `0` | update suppression |
| 2 | `-base_delta` | 等范数反向 |
| 4 | `-3 × base_delta` | 放大反向 |

算子级预算为：

```text
||crafted_delta - base_delta|| / ||base_delta|| = b
```

base norm 为零时保持零 update，记录 displacement ratio=0，不制造无来源方向。

### `AttackCapabilities` / `AttackKnowledge`

六个受审计维度：

```text
global model
local data
benign updates
other-client data
private diagnostics
oracle data
```

本阶段内建攻击声明：

| Capability | 需要/观察 |
|---|---:|
| global model | 是 |
| own local data | 是 |
| benign updates | 否 |
| other-client data | 否 |
| private diagnostics | 否 |
| oracle data | 否 |

engine 构造时冻结 capability manifest；每轮在 sampling 前检查 manifest 未变化，并重新验证 knowledge。

### `AttackContext`

只包含：

```text
client_id
round_index
global_model
```

不包含 task id、server component state、benign updates、malicious identity 集合或 oracle diagnostics。

### `ScopedLocalTrainer`

内建攻击只能接收 scoped trainer。fixture 装配时：

```text
benign trainer datasets    = clients {3,4,5}
malicious trainer datasets = clients {0,1,2}
```

scope 与 fixed malicious population 不一致时，engine 构造失败。

### Generator protocol

```python
class MaliciousUpdateGenerator(Protocol):
    capabilities: AttackCapabilities

    def craft(
        self,
        context: AttackContext,
        rng: RandomSource,
    ) -> ClientUpdate: ...
```

`IdentityMaliciousUpdateGenerator` 与 `DeltaReversalAttack` 可互换，AttackRoundEngine 不需要修改。

## 5. Round 数据流

```text
RoundState parent RNG snapshot
        ↓
shared round kernel
        ↓
sampling child RNG → sampled client IDs
        ↓
per-slot client child RNGs
        ↓
FixedMaliciousPopulation.contains(client_id)
  ├── false → benign LocalTrainer
  └── true  → sanitized AttackContext
                  ↓
              malicious generator
                  ↓
              ClientUpdate(is_malicious=True)
        ↓
ordered ClientUpdate tuple（保持 sampled order）
        ↓
FedAvg
        ↓
ServerSGD
        ↓
RoundTransition + parent RNG snapshot
```

transition 为报告保留 benign/malicious 分组，但 aggregator 消费的是原始 sampled order，避免浮点求和顺序或 order-sensitive aggregator 被身份分组改变。

真实 malicious IDs 只写入 `private_diagnostics`，不写入 `public_signals`。

## 6. Matched Episode 数据流

每个 seed 创建相同的：

- train/held-out datasets；
- IID partition；
- initial model；
- initial parent RNG snapshot；
- sampler、FedAvg、ServerSGD 与 horizon。

然后分别运行：

```text
clean RoundEngine
identity AttackRoundEngine
delta-reversal AttackRoundEngine (b=2)
```

held-out evaluator 只在 Episode 完成后读取 final model。`security` 静态依赖测试禁止导入 canonical oracle evaluation 层。

## 8. 预期结果

### Identity gate

clean 与 identity 必须具有完全相同的：

- sampled clients；
- parent RNG snapshots；
- aggregate deltas；
- global model trajectory；
- final held-out loss/accuracy。

### Delta-reversal gate

- sampled clients 与 parent RNG trajectory 仍与 clean 相同；
- 每个恶意 update 的算子语义满足 `b=2`；
- 三个声明 seed 的 final paired loss harm 全部为正；
- accuracy harm 单独报告，不要求 loss 上升时 accuracy 必然立即下降。

## 9. 实际结果

### Clean 与 identity

三个 seed 的 clean/identity final metrics 分别逐元素相同，并且逐轮 aggregate、model 与 parent RNG snapshot 完全相同。

### Delta reversal `b=2`

|---:|---:|---:|---:|---:|---:|---:|
| 301 | 0.0313416056 | 0.9851003647 | 0.9537587591 | 1.0 | 0.0 | 1.0 |
| 302 | 0.0315583041 | 0.4858599782 | 0.4543016741 | 1.0 | 1.0 | 0.0 |
| 303 | 0.0316052074 | 0.2420081735 | 0.2104029661 | 1.0 | 1.0 | 0.0 |

每轮实际 malicious client count：

```text
seed 301: 2,2,2,3,2,2,2,2
seed 302: 3,2,1,2,2,1,3,2
seed 303: 3,2,2,2,1,1,2,1
```

三个 seed 的 loss harm 全部为正。Seed 302/303 的 accuracy 尚未下降，但 loss 分别增加约 0.4543/0.2104，说明模型置信度和 margin 已退化，离散 accuracy 尚未越过决策边界。不能只看 accuracy 判断攻击无效。

## 12. 限制与 Gate 结论

限制：

- 结论只适用于本报告声明的 synthetic fixture、三个 seeds、50% malicious population、FedAvg 和 `b=2`；
- capability 是可信插件的可审计 contract，不是阻止任意恶意 Python 代码的安全沙箱；
- 当前只证明 own-update delta reversal，不证明 IPM、ALIE、LMP、backdoor 或 adaptive attack；
- 当前没有 robust defense；
- accuracy 并非所有 seeds 都下降，主要 E1.1 harm 指标是 paired held-out loss；
- 三个 seeds 用于阶段 gate，不足以作为最终论文统计结论。

E1.1 gate 要求 identity exact equivalence、算子预算正确、matched sample/RNG、三个声明 seeds 的正 loss harm、capability compliance 和 oracle isolation。最终 canonical 133 项、全仓相关 453 项及依赖边界 3 项测试全部通过，独立审查无未解决问题，因此本阶段判定通过。
